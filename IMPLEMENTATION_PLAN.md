# План реализации системы «Начисление»

Документ отражает фактическое состояние проекта на 11 сентября 2026 года.

## Принятые решения

- Стек: Django, PostgreSQL, openpyxl, Django templates, Docker Compose.
- Сотрудник имеет автоматически назначаемый табельный номер и глобальные
  часовую/дневную ставки. Изменение ставки влияет на расчёт всех открываемых
  периодов; отдельной истории ставок по месяцам нет.
- Плюс и минус прошлого месяца переносятся автоматически, если администратор не
  зафиксировал ручную корректировку.
- Оклад хранится в месячной записи начисления. Новый месяц получает оклад из
  непосредственно предыдущего месяца только при первом создании записи.
- Табель импортируется по именам колонок, а не по координатам ячеек.
- Реальный файл табеля автоматически в production не импортируется.

## Формулы

```text
Начислено дни = Дни * Ставка день
Начислено часы = Часы * Ставка час
Итого с КТУ = Начислено часы * КТУ
Итого = Итого с КТУ + Начислено дни + Премия

Если Дни = 0 и Часы = 0:
Итого = Оклад + Премия

Итого выдано = ЗП 1С + Суточные 1С + сумма выплат
Остаток = Итого - Итого выдано + Плюс за пред. месяц - Минус за пред. месяц
```

## Этапы

### 1. Каркас, пользователи и периоды — реализовано

- Django-проект, PostgreSQL, Compose, авторизация.
- Роли «Администратор» и «Руководство».
- Открытые, закрытые и архивные расчётные периоды.

### 2. Сотрудники и глобальные ставки — реализовано

- Карточка сотрудника, алиасы ФИО, автоматический табельный номер.
- Типы `ИТР` и `Рабочий персонал`.
- Организации `Подрядчик`, `СЗ`, `ИП`, `СПЕКТРУМ-С`.
- Глобальные часовая и дневная ставки, ручное изменение и отдельный импорт.
- Стабильная сортировка ФИО от А до Я.

### 3. Импорт табеля — реализовано

- Поиск обязательных заголовков `Сотрудник`, `Дни`, `Часы` в первых 20 строках
  всех листов, независимо от порядка колонок.
- Выбор единственного листа с максимальным числом колонок-дней.
- Итоговые `Дни`/`Часы` берутся из одноимённых колонок; дневные колонки остаются
  расшифровкой.
- Необязательные метаданные, статус и ставки с предпросмотром и валидацией.
- Пропуск пустых строк, разделов `УВОЛЕННЫЕ` и строк `Итого`.
- Атомарное повторное применение с обновлением сотрудников и ставок.

### 4. Начисление, выплаты и аудит — реализовано

- Новая формула расчёта и отдельное правило оклада для нулевых строк.
- Помесячный оклад и перенос его в новый месяц.
- Ручные поля 1С, премия, КТУ и корректировки переноса.
- Выплаты; инициатор автоматически берётся из текущей учётной записи.
- Автоматический перенос плюса/минуса и журнал изменений.
- Руководство меняет премию, КТУ и выплаты; оклад и остальные поля — только
  администратор.

### 5. Фильтры и экспорт — реализовано

- Поиск по части ФИО без учёта регистра.
- Выпадающие фильтры организации, проекта и типа из полной таблицы выбранного
  периода.
- Должности берутся только из уникальных значений `Employee.position` доступных
  строк периода. Нулевые должности появляются только в соответствующем режиме;
  изменения карточек сотрудников отражаются сразу.
- Нулевые строки скрыты по умолчанию, включаются флагом `show_zero=1` либо
  показываются отдельно флагом `only_zero=1`.
- Экспорт применяет те же фильтры и выгружает тот же набор сотрудников.
- Поле сотрудника в форме выплаты поддерживает ввод ФИО и выпадающие подсказки.

### 6. Приёмка и развёртывание — локальная проверка завершена

- Автотесты форматов импорта, формул, переноса оклада, фильтров, сортировки и
  прав доступа: 11 тестов проходят на PostgreSQL 17; проверки конфигурации
  также проходят на SQLite.
- Контрольный файл июня: 135 сотрудников, из них 48 нулевых, ошибок импорта 0.
- Локальный Compose собран; миграция `0007`, основные страницы и экспорт
  проверены.
- Перед миграцией production-БД: `pg_dump`.
- Пересборка трёх production-сервисов, миграция, healthcheck, HTTPS и просмотр
  журнала запуска — отложены до отдельного подтверждения развёртывания.

### 7. Портативный Windows-лаунчер — реализовано

- Один `AccrualPortable.exe` для Windows x64, без установки Python, Docker и
  PostgreSQL.
- Окно со статусом, кнопками включения/выключения, ссылкой, логином, паролем и
  кнопками копирования.
- Чистая SQLite-база, миграции и администратор создаются автоматически при
  первом включении; изменяемые данные хранятся рядом в `AccrualData`.
- EXE собран и автономно проверен через Wine: страница входа, статика,
  учётная запись и корректное завершение сервера.
